## 📝 核心知识点总结

### 1. Agent 基本概念

**定义**：Agent 是能够感知环境、做出决策、执行行动的智能体。

**核心组成**：
- **LLM（大脑）**：理解和生成语言，进行推理和决策
- **Memory（记忆）**：存储上下文信息，维护对话历史
- **Tools（工具）**：扩展能力边界，执行具体操作
- **Planning（规划）**：分解和执行任务，制定行动计划

---

### 2. 三种经典范式

#### ReAct (Reasoning + Acting)
```
Thought → Action → Observation → 循环/结束
```
- **特点**：动态反应式，边想边做
- **适用**：需要外部工具交互的任务
- **优势**：高可解释性，动态纠错
- **劣势**：可能陷入循环，依赖模型格式遵循能力

#### Plan-and-Solve
```
Plan(规划) → Execute(执行)
```
- **特点**：预先规划式，先谋后动
- **适用**：结构性强、可分解的任务
- **优势**：结构清晰，步骤明确
- **劣势**：计划静态，无法动态调整

#### Reflection
```
Execute → Reflect → Refine → 循环/结束
```
- **特点**：迭代优化式，自我改进
- **适用**：对结果质量要求高的任务
- **优势**：显著提升输出质量
- **劣势**：调用成本高，实时性差

---

### 3. 三种范式对比

| 维度 | ReAct | Plan-and-Solve | Reflection |
|------|-------|----------------|------------|
| **决策模式** | 动态反应式 | 预先规划式 | 迭代优化式 |
| **执行顺序** | 边想边做 | 先规划后执行 | 边做边改 |
| **历史处理** | 列表追加 | 字符串累加 | Memory 类 |
| **核心机制** | 都是将历史追加到提示词中传递给 LLM |

---

### 4. 历史处理机制（重要发现）

**三种范式的历史处理本质相同**，只是封装方式不同：

| 范式 | 存储结构 | 格式化方式 |
|------|----------|------------|
| ReAct | `list[str]` | `"\n".join(history)` |
| Plan-and-Solve | `str` | 直接累加 |
| Reflection | `Memory` 类 | `get_trajectory()` |

## 💡 心得体会

### 最有收获的内容

1. **范式选择**：没有万能方案，应根据任务特征选择合适范式
2. **提示词工程**：精确的格式说明是 Agent 稳定运行的基础
3. **历史传递**：三种范式本质都是将历史追加到提示词中
4. **工具扩展**：可以添加本地工具避免外部 API 依赖
